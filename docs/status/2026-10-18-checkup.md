### B-1 (hoch) — Push ist blockiert: 134 Commits Rückstand, Credential-Helper defekt

**Gemessen:**

```
git rev-parse --short HEAD          → 3f9abbb   (2026-10-15 19:31)
git ls-remote origin refs/heads/main → e1fb1d9  (2026-10-14)
git rev-list --count origin/main..HEAD → 134

Get-Command git-credential-gh        → (nichts)
```

`git ls-remote` meldet dazu: `git: 'credential-gh' is not a git command. See 'git --help'.`

**Gedeutet:** Der konfigurierte Helper `gh` erwartet ein Programm `git-credential-gh`,
das es auf dieser Maschine nicht gibt (installiert ist `gh.exe` unter
`C:\Program Files\GitHub CLI\`). Lesen geht anonym, **Schreiben** (Push) kann so nicht
authentifizieren. Der Rückstand von 134 Commits ist die Folge — nicht der einzige Grund
(vielleicht wurde auch einfach nicht gepusht), aber ein Push wäre derzeit ohnehin rot.

**Nachprüfen / beheben:**

```powershell
gh auth status
gh auth setup-git          # setzt credential.https://github.com.helper = !gh auth git-credential
git config --get credential.https://github.com.helper
git push                   # erst danach
```

### B-2 (hoch) — `PMH_TEST_DATABASE_URL` zeigt auf die Betriebsdatenbank

| `packages/api/auth-http/tests/postgres.test.ts` | 1 | „dieser Test LÖSCHT ALLE BENUTZER und zeigt auf `pmh`“ |

**Gedeutet:** Die fünf **Schutzriegel funktionieren** — sie brechen ab, statt die
Betriebsdatenbank zu löschen. Das ist ein gutes Zeichen. Sie sind aber rot, weil die

**Beheben:** `PMH_TEST_DATABASE_URL` in `.env` auf `pmh_test` setzen (existiert und steht
laut Schema-Prüfung auf Fassung 10). Danach sollten 12 der 13 Tests grün sein.

### B-3 (mittel) — `apps/cli/src/main.ts` startet den Host beim Import

**Gemessen:** In der Testsuite erscheint ein `Unhandled error between tests`:

```
error: pmh: startup failed: 2 required plugins did not activate
  ptc-runtime   (@deepseek-ai/dsh-ptc-runtime-node)  failed to import
  webserver     (@deepseek-ai/dsh-host-webserver)     Error at serve
      at async boot (.../dsh-app-boot/lib/index.js:4242:9)
      at async main (apps/cli/src/main.ts:464:21)
```

Und im Quelltext:

```
apps/cli/src/main.ts:505   await main()          ← ohne Import-Wächter
apps/cli/tests/flags.test.ts:22  import { parseHostFlags } from '../src/main.ts'
```

**Gedeutet:** Der Flag-Test importiert eine Funktion aus `main.ts`; der Import führt die
letzte Zeile aus und **bootet den kompletten Host** — mit dem Profil der laufenden
Instanz. Das scheitert (Port/Plugin) und erscheint als unbehandelter Fehler „zwischen
den Tests“. Ein Modul, das beim Import Prozesse startet, ist nicht testbar; der Fehler
ist reproduzierbar und unabhängig von der Datenbank.

**Beheben:** `if (import.meta.main) { await main() }` (Bun) bzw. den Einstieg in eine
separate Datei ziehen, die `main.ts` nur exportiert.

Projektdefekt verbuchen, aber auch nicht als „grün“ zählen.
