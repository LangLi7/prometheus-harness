# Office to PDF

[English](office-to-pdf.md) | 中文

The [document package family](../../packages/document/README.zh.md) converts Office files to PDF on a Node host. Consumers own source-read authorization and presentation; the shared provider owns conversion, bounded admission, and temporary PDF reuse. This subsystem creates no model-facing tools or Session events.

## Ownership

| Owner | Responsibility |
|---|---|
| [office-to-pdf](../../packages/document/office-to-pdf/README.zh.md) | `ctx.officeToPdf`: shared LibreOffice conversion, bounded admission, and the PDF cache |
| [Web bundle](../../packages/bundle/web-app/README.zh.md) | The single configurable conversion provider shared by host consumers |
| [Office preview Client](../../packages/client/ui-sidebar-documentpreview/README.zh.md#office-preview) | Office extension selection, PDF reuse, and missing-font notices |

## Requests and results

[`OfficeToPdfRequest`](../../packages/document/office-to-pdf/src/types.ts) contains an already-authorized source key/version, optional stat size, a deferred `read(signal, maxBytes)` callback, foreground/background priority, and a `OfficeExtension`: `doc`, `docx`, `xls`, `xlsx`, `ppt`, or `pptx`. `OfficeToPdf.convert(request, signal?)` returns one complete PDF result. Cancellation follows the caller and provider lifetimes; validation, output, and engine failures reject with a classified `OfficeToPdfError`.

`OfficeToPdfPriority` is `foreground` for requested preview/QA and `background` for speculation. `OfficeSourceKey` brands the caller-owned authorized source locator. `OfficeToPdfGeneration` brands a provider lifetime, and `OfficeToPdfKey` brands its content identity; neither opaque value is parsed by consumers.

| Result field | Meaning |
|---|---|
| `pdf` | Caller-owned `Uint8Array` containing the complete PDF |
| `missingFonts` | Requested document font families unavailable to this conversion |
| `cacheKey` | Opaque converter generation plus extension/source-content identity |
| `generation` | Provider lifetime; replacement invalidates cached PDF reuse |

The provider admits the deferred read before allocating source bytes, shares conversions by content identity, and removes its private scratch directory before returning. Returned PDF bytes remain valid after provider disposal. Source and PDF bytes do not enter Session storage. Consumers can use [Workspace Files](../../packages/api/workspace-files/README.zh.md) for authorized bounded reads.

## Preview reads

`RenderedDocumentBytes` carries workspace-file metadata, native PDF `data`, `missingFonts`, and `generation`; a converted PDF keeps the original source-file identity.

The `officeToPdf.render` Remote method checks source authorization and version through the Session's [Workspace Files](../../packages/api/workspace-files/README.zh.md) service. After conversion capacity is acquired, `fs.readBytes` supplies the raw input within the reserved byte capacity; that read is bounded by the Office input ceiling. The binary Remote projects the PDF as a multipart attachment and the Client restores it as an `ArrayBuffer`-backed `Uint8Array`. Source access failures pass through directly; size and engine failures expose only the classified reason without diagnostics. Conversion neither activates an Agent nor appends events.

`api/remotes` mounts the Remote descriptors generated by the conversion service. The shared document preview package registers Office formats using full-byte loading and the existing PDF.js worker. Every preview read rechecks the rendering generation, source authorization, and version before sharing an in-flight conversion or cached PDF. Connection reset and plugin unload cancel requests and clear cached bytes. A missing service shows localized configuration guidance.

## Engine selection and limitations

The external [`@deepseek-ai/libreoffice-kit`](https://github.com/deepseek-ai/dsh-libreoffice-kit) Node API selects its prebuilt engine. The kit maintains version and release process independently, and the [release-ownership decision](../../.agents/notes/implemented/architecture/2026-09-14-independent-libreoffice-kit.zh.md) defines the exact ownership. Application builds install the published npm package. Application packaging requires a native engine declared for the target; when the kit declares no native engine for that target, Node WASM is used. The [platform engine reference](../../packages/document/office-to-pdf/README.zh.md) defines installation and packaging rules. Invalid metadata, missing required resources, and conversion errors all reject the request without switching engines. Conversion uses disk input/output paths on the Host, not a browser conversion engine or font RPC.

[Host provider configuration](../../packages/document/office-to-pdf/README.zh.md#use-this-package) owns concurrency, deadlines, input/output ceilings, archive ceilings, image resolution, and font access. Native/WASM implementations and asset distribution belong to the kit workspace. System LibreOffice probing, runtime engine downloads, a persistent PDF cache, and model-facing rendering are not part of this provider.
